## 結果

## 方法と限界

国土交通省[国土数値情報 鉄道データ2025年度](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N02-2025.html)（CC BY 4.0）を加工。基準日2025-12-31、公開更新2026年4月。N02-25_Station.geojsonの事業者名・路線名・駅名で対応し、なんば/難波、なかもず/中百舌鳥、あびこ/我孫子を正規化した。134件すべてが一意に対応した。

旧座標から駅LineStringまでの最短距離を局所的なメートル座標で算出。50mは変更対象を絞る監査基準で、公式の精度保証ではない。修正値はHaversine距離で重み付けしたLineStringの長さに沿う中点を小数6桁に丸めたもの。公式が定義する駅中心・入口・改札の座標ではない。各線別駅レコードを持つこのAPIでの位置検索や駅間距離に合わせた代表点の改善であり、従来値が駅施設全体の代表点として必ず不正という意味ではない。

N02の座標系はJGD2011、CSVはWGS84を要求する。厳密な時点・測地系変換は実施せず、この50mしきい値での位置監査では近似的に扱った。測量用途やサブメートル精度を保証しない。地下駅の実測ではない。公式駅案内・構内図は路線別ホームと乗換動線の補助資料であり、座標値の直接根拠はN02である。公式PDFを全件画像確認したものではない。

## 検証

- 134件の一意な照合、座標範囲、全件の有限数値を確認。
- 全18修正点が独立再計算したN02線形の長さ中点から0.15m以内であることを確認。
- CSVの行数・順序・IDと緯度経度以外の列が不変、変更は18行だけであることを確認。
- 修正後の134件を再照合し、50m超の点が0件になることを確認。
- `git diff --check` を実行。
- WSL UbuntuのPython 3.14.4でも独立した全134件の照合と変更範囲検証に成功。
- `cargo run -p data_validator` はWindows側・WSL Ubuntu（kitten）側のPATHおよび標準配置先にcargoが見つからず実行不可。Rustのfmt/clippy/testも未実行。既存のCIによる検証が必要。

## 再現

`python3 scripts/audit_osaka_metro_coordinates.py . /path/to/N02-25_Station.geojson [修正前CSV]` でPython標準ライブラリのみを使って再照合できる。上記N02 ZIPのUTF-8/N02-25_Station.geojsonを指定する。修正前CSVを省略すると座標照合だけを実行し、指定すると18行の緯度経度だけを変更したことも検証する。監査対象が増えた場合は件数・路線対応表・しきい値を再検討する。
